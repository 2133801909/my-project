# ADR 0005：演示账号边界

- 状态：已接受
- 日期：2026-11-03

## 背景

产品需要展示登录/注册/多用户资料切换，但没有后端，也不能让用户误以为这是真实认证。

## 决策

- 账号仅由**昵称**标识；不收集密码、验证码、学校账号。
- 注册 = 在 localStorage 创建 `campus-life-demo-account:<name>` 快照。
- 登录 = 读取同名快照；不存在则提示先注册。
- 会话存 `sessionStorage`，关闭标签页后失效（账号快照保留）。
- 访客直接进入，使用全局快照。
- 退出先保存当前状态，再清空会话。
- UI 明确声明：“仅按昵称在当前浏览器保存不同资料，不验证身份、密码或学校账号”。

## 禁止

- `input[type="password"]`、密码存储、密码校验逻辑；
- 任何网络请求、OAuth、真实 token；
- 以“登录成功”暗示身份已验证。

## 后果

- 同一浏览器内昵称即身份，改名不会迁移账号快照；
- 昵称大小写不敏感（存储键统一小写）；
- 清除 localStorage 会丢失全部演示账号。

如未来接入真实认证，必须新增 ADR 并重新设计会话、权限与数据隔离。
