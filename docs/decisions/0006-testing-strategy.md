# ADR 0006：单元 + 组件测试策略

- 状态：已接受
- 日期：2026-11-03

## 背景

旧版测试大量使用 `fs.readFileSync` + 正则匹配源码/CSS，导致重构时测试与实现耦合，却无法证明用户行为正确。

## 决策

- 测试分三层：领域单测、reducer 单测、React 组件测试。
- 使用 Vitest + jsdom + Testing Library；查询优先角色、label、文本，不查 class。
- 存储测试使用内存实现；组件测试通过 `renderWithProviders` 注入固定时钟与会话。
- 不引入端到端框架；关键路径用真实浏览器冒烟补充。
- 回归测试以行为命名，并注明修复的缺陷。

## 后果

正面：

- 重构不会因模板字符串变化而误报；
- 测试执行快（< 1s），可在每次提交运行；
- 领域规则获得稳定保护。

负面：

- 无自动化的真实浏览器/媒体流测试；
- 无覆盖率门槛，依赖评审判断；
- 组件测试仍可能因文案调整而失败，需同步更新。

## 规则

- 不为“能跑”而写 `not.toThrow()` 或空断言。
- 不测试第三方库、CSS 字符串、组件内部 state。
- 修改公开文案时同步更新相关角色/文本查询。
